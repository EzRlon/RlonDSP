# GitHub 操作规范（长期有效）

本文件规定维护者（含自动化助手）在操作 GitHub 时必须遵守的流程与确认机制。

账户信息见 [GITHUB.md](./GITHUB.md)（用户名 **EzRlon**）。

---

## 一、总原则

1. **先报告，后执行。** 任何写操作（推送、创建仓库、发布 Release）先输出清单，等用户回复 **"确认推送"** 后才执行。
2. **删除必须二次确认。** 任何删除操作先输出清单，等用户回复 **"确认删除"** 后才执行。
3. **不碰敏感信息。** 不把 Token、密钥、密码写入任何文件，也不提交进仓库。
4. **不改账户设置。** 未经确认，不修改仓库可见性、协作者、Webhook 等账户/仓库设置。
5. **不破坏历史。** 强制推送、删除远程分支、覆盖远程历史，必须单独二次确认。

---

## 二、标准流程

### 1. 用户说「把某某项目同步到我的 GitHub」

1. 检查项目的 `git` 状态（当前分支、未提交改动、是否有 `.git`）。
2. 检查/生成 `.gitignore`，确保排除：`node_modules`、`dist`、`build`、`release`、`target`、`*.log`、`.env*`、备份目录。
3. 输出**改动清单**（将提交哪些文件、多少行、目标仓库名与分支），等待「确认推送」。
4. 确认后：提交 → 检查远程仓库是否存在（不存在则用 `gh repo create` 创建 **Public**、**不初始化 README**）→ 推送 `main` 分支。
5. 报告仓库地址与结果。

### 2. 用户说「把当前项目更新到 GitHub」

1. 检查改动。
2. 输出改动清单，等待「确认推送」。
3. 确认后：提交 → 推送 → 报告结果。

### 3. 用户说「删除我 GitHub 上的某个文件」

1. 确认文件在哪个仓库、哪条分支、什么路径。
2. 输出确认清单：仓库 / 分支 / 文件路径 / 影响范围 / 是否可恢复（Git 历史中仍可找回）。
3. 等待「**确认删除**」。
4. 确认后：用 `gh api` 删除该文件并提交，报告结果。

### 4. 用户说「删除我 GitHub 上的某个项目 / 仓库」

1. 确认仓库名与所有者。
2. 输出确认清单：仓库全名 / 可见性（Public 或 Private）/ 影响范围 / **是否可恢复（GitHub 删除仓库后通常不可恢复）**。
3. 等待「**确认删除**」（属破坏性操作，需用户明确二次确认）。
4. 确认后：`gh repo delete <owner>/<repo> --yes`，报告结果。

### 5. 用户说「给某某项目创建一个 Release」

1. 确认版本号（如 `v1.0.0`）、Release 标题、产物文件路径。
2. 输出确认清单：标签 / 标题 / 说明来源（如 CHANGELOG.md）/ 将上传的文件清单与大小。
3. 等待「确认推送」。
4. 确认后：`gh release create <tag> <文件...> --title <标题> --notes-file <说明文件>`，报告 Release 地址。
5. 若该标签已存在，先告知用户并询问是**移动标签**还是**改用新版本号**。

## 三、安全红线

| 禁止事项 | 说明 |
|---|---|
| 未经确认就推送 | 必须先出清单并等「确认推送」 |
| 未经确认就删除 | 必须先出清单并等「确认删除」 |
| 强制推送 / 覆盖历史 | 必须单独二次确认 |
| 提交 Token / 密钥 | 任何情况下都不允许 |
| 修改账户或仓库设置 | 未经确认不允许 |
| 删除 `optimize-baseline` 标签与本地备份 | 不允许（回滚锚点） |

---

## 四、认证方式

使用 GitHub CLI 的设备授权（已验证登录为 **EzRlon**）。

- 凭据保存在系统凭据库，不落盘为明文文件。
- Git 的凭据助手已指向 gh，`git push` / `git pull` 自动认证。
- 如需重新登录：`gh auth login`；如需补权限：`gh auth refresh -s repo,read:org,workflow`。

命令直接使用 `git` 与 `gh`。若二者未加入系统 `PATH`，请先将其所在目录加入 `PATH`，或在命令中改用完整路径。
